06 · Detection engine

YAML in, compiled regex + optional sliding window out. Code: internal/detect. Content: rules/web.yaml (also embedded).

Reviewed 2026-08-14 pattern + threshold
Kinds YAML schema Load order Your rules

Two kinds

kindFires whenExample
pattern (default) Any listed field matches the regex (after pre-filters). web.sqli.union on decoded URL
threshold N matching events from the same group_by key inside window. Then the window resets so we do not alert every extra hit. 25 × 404 from one IP in 60s → web.scan.404storm
snoop Distinct interesting paths, human-paced gaps (min_gap), optional empty referer and low static-asset ratio. Slow /admin → /.env walk → web.snoop.secret_hunt. See 14.
One event, many alerts A sqlmap GET with UNION SELECT can fire both web.scanner.ua and web.sqli.union. That is intended. Filter the UI by severity if the feed is loud.

Load order

  1. On-disk ./rules or <exe-dir>/rules if that directory exists and parses.
  2. Else the embedded copy of rules/web.yaml.
  3. Then --rules path is appended (does not replace built-ins).

Edit rules/web.yaml next to the binary and restart to take effect. There is no hot reload in v0.1.

Add a site-only rule

# rules/local.yaml
rules:
  - id: site.admin.probe
    title: Admin path probe
    severity: medium
    category: recon
    mitre: [T1595.002]
    fields: [path]
    pattern: '(?i)^/(admin|backoffice)/'

Then: gpewebdefender serve --tail … --rules rules/local.yaml

This is the product lever Generic SQLi is table stakes. Paths only your app has are how the monitor becomes yours. Catalog those on 12 as you learn them.
