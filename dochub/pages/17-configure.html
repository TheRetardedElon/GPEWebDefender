Tell the monitor about failed logins / IDOR / canaries the access log cannot see App POSTs JSON to /api/ingest. Fire-and-forget. Chapter 19. Not a new webhook product. Same token as the agent. Never send passwords.
Watch WordPress / Drupal / Joomla paths (or use them as extra honey) --rules packs (loads packs/cms.yaml). Off by default. Not a plugin scanner. Paths only.
Create operators, change your dashboard password Settings → Your account / Operators. First admin is /login or SIEM_ADMIN_*. 18. Not htpasswd. Not the ingest token.
See a visual breakdown (volume, MITRE, countries, hosts) Reports → Insight. 1h / 24h / 7d is a real clock window. Click a bar to Search. Not a second database. Same alerts.

You never type a monitored box’s IP into Settings. The agent on that box ships the logs. Settings only needs the name if you want a separate pin.

Add a host (checklist)

  1. Copy the same binary to the new box.
  2. Give it the same ingest token as the manager.
  3. Start the agent: --url (manager) · --name (stable label) · --tail and/or --journal.
  4. On the manager, allow that box’s IP to the ingest port.
  5. Open the UI. The name should appear in Hosts after the first line arrives.
  6. Optional: Settings → add a row with that same name and a map location.
No HTTP logs? A Linux box can still run --journal only. It will show up under Reports → Auth · Linux. A database with no SSH and no web server does not need an agent.

The agent does not scan the network and does not walk the disk. If a file is not tailed and journald is off, that host is silent.

App / platform login failures

Access logs cannot see a failed password in a POST body. The application (or API gateway) POSTs a small JSON event. Full field list: 16. Never send the password. 

POST /api/ingest
Authorization: Bearer SECRET
Content-Type: application/json
X-SIEM-Source: app-api

{ "kind": "applogin", "src_ip": "203.0.113.9", "user": "alice",
  "path": "/api/login", "status": 401, "outcome": "fail", "method": "LOGIN" }
