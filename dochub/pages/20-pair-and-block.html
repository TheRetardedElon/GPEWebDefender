20 · Pair a host and block an IP

Optional. Log shipping still works with the shared ingest token. Pairing is how your monitor is allowed to tell your sensor to ban an IP on that box’s firewall. Same steps on any deployment.

Added 2026-08-16 Admin only

What this is not

  • Not a WAF. Traffic is not proxied.
  • Not the manager SSHing into the host. The sensor pulls orders.
  • Not automatic. An admin clicks Block. Rules do not ban on their own.
  • Not something a viewer or the ingest token can do.

Three human steps

  1. Enrollment phrase — you invent this in Settings → Paired hosts. At least 12 characters. Stored as Argon2id. Never shown again. This is unique to your install.
  2. One-time code — Pair a host… mints ABCD-2341. Lives 15 minutes. Single use. Hashed at rest.
  3. Approve — the host appears as pending with a fingerprint and the IP it called from. You look at it. Approve or Reject.

After Approve the host gets its own key in /etc/gpewebdefender/agent.json (mode 0600). That key is the only thing that can pick up block orders or answer a Status check for that name.

On the host

gpewebdefender pair \
  --url https://YOUR-MONITOR \
  --name web-1 \
  --code ABCD-2341 \
  --block fail2ban

# then, same as before:
gpewebdefender agent --url https://YOUR-MONITOR --name web-1 \
  --tail /var/log/nginx/access.log --journal

It will ask for the enrollment phrase. Or pass it in the environment as GWD_PAIR_PHRASE if you are scripting (do not commit that).

--block is fail2ban, ufw, windows, or off. Local off wins — the dashboard cannot override it. The agent will try to install a dedicated fail2ban jail named gpesiem if it is missing. A hand copy lives in deploy/fail2ban-gpesiem.jail and deploy/fail2ban-gpesiem.filter.

The install script accepts the same flags: install-agent.sh --url … --name web-1 --tail … --code ABCD-2341 --block fail2ban.

Already shipping logs?

Leave it. The old ingest token still works. Pairing is extra.

  1. Put a binary that includes pair (0.9.19+) on that host. Same file as the manager.
  2. Mint a code on the manager. Run pair with the same --name the agent already uses.
  3. Approve the fingerprint.
  4. Point the agent unit at --cred /etc/gpewebdefender/agent.json and restart it so it can poll for orders. deploy/gpewebdefender-agent.service.example already has that flag.

The dedicated fail2ban jail is gpesiem. It is not the sshd jail. Local sshd fail2ban you already run stays yours.

Blocking from the dashboard

Open an alert. If that host is paired and you are an admin: Block on this host 1h / 24h, or all paired hosts. Confirm. The sensor picks the order up within a few seconds.

Rails:

  • Public unicast IPs only. No RFC1918, loopback, link-local, CGNAT.
  • Will not ban the host’s own seen address or your current session IP.
  • Durations: 15m, 1h, 24h, 7d, or until you unban.
  • Cap of 200 active bans per host. Commands expire in 2 minutes if the sensor is down.
  • Audit row: who, which IP, which host, how long.

Unpair: Revoke on the host row. That key dies. Log shipping with the shared ingest token can continue.

API (for operators writing glue)

CallWho
POST /api/pair-phraseadmin session
POST /api/pair-codesadmin session — returns the code once
POST /api/agent/pairopen, rate-limited — phrase + code + name
GET /api/agent/commandsthat host’s key, only after Approve (ban / unban / list / stats)
POST /api/agents/{id}/banadmin session

The ingest Bearer cannot mint codes, approve, or ban.

Status checks use the same channel

After Approve, an admin can open Status and click Check. The sensor posts one snapshot (load, memory, disk) and stops. Same poll as block orders. Binary 0.9.25+. Chapter 21.
