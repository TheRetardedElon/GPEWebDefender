Pick a shape first

If you skip this, you will install the wrong thing and think it is broken.

Your situationWhat you install
You just want to see the screens gpewebdefender demo on your laptop. Fake attacks. Not your site.
One Linux box that already has nginx / Caddy and the access log All-in-one. The manager tails that log itself. No agent.
A small extra box for the monitor, and one or more web servers Split. Manager on the extra box. One agent on each web (or SSH) host.
Do not expose port 8787 to the internet The default bind is 127.0.0.1:8787. Reach it with an SSH tunnel until you put HTTPS + login in front. Health is unauthenticated.

Look first (any OS)

  1. Build or download the binary for this computer (see Build).
  2. In the repo folder, run gpewebdefender demo (Windows: gpewebdefender.exe demo).
  3. Open http://127.0.0.1:8787.
  4. You will see fake shots on the map. That is not the internet attacking you. Read 04 before you panic.

Method A — the script does it

Linux + systemd + root. You still have to know the path of your access log and a name for each host.

All-in-one (one box, has the log)

# from the repo, as root
chmod +x deploy/install-manager.sh deploy/install-agent.sh
sudo ./deploy/install-manager.sh --all-in-one \
  --tail /var/log/nginx/access.log \
  --journal \
  --home 40.7,-74.0

Split (monitor box first)

# on the monitor
sudo ./deploy/install-manager.sh --home 40.7,-74.0

# on each web / SSH box
scp root@MONITOR:/usr/local/bin/gpewebdefender /usr/local/bin/gpewebdefender
scp root@MONITOR:/etc/gpewebdefender/env /etc/gpewebdefender/env
sudo ./deploy/install-agent.sh \
  --url http://MONITOR:8787 \
  --name web-1 \
  --tail /var/log/nginx/access.log \
  --journal

Replace MONITOR with the monitor’s private hostname or IP. Replace web-1 with a short name you will recognize. Replace the log path if you use Caddy / Apache / JSON.

What the script actually does Creates the gpewebdefender user, writes a random token to /etc/gpewebdefender/env if missing, copies the binary + rules + this DocHub, installs systemd, starts the unit. It will not overwrite an existing token.

Method B — you type every step

Same result as A. Use this if you do not want a script, or you are not on systemd.

  1. Copy the Linux binary to /usr/local/bin/gpewebdefender and chmod +x it.
  2. useradd --system --home /var/lib/gpewebdefender --shell /usr/sbin/nologin gpewebdefender
  3. Copy rules/ and dochub/ into /var/lib/gpewebdefender/. chown -R gpewebdefender:gpewebdefender.
  4. Copy deploy/env.example to /etc/gpewebdefender/env. Put a long random value in GWD_TOKEN. Mode 640.
  5. Copy deploy/gpewebdefender.service.example to /etc/systemd/system/gpewebdefender.service. Edit listen / home / tail if you need them.
  6. systemctl daemon-reload && systemctl enable --now gpewebdefender
  7. For each other host: copy deploy/gpewebdefender-agent.service.example, set --url, --name, --tail, same token. Optional later: pair that host (ch. 20) so it can take block orders.

Full unit files and nginx: 10 and deploy/README.md.

After it starts (do these in order)

  1. From your laptop: ssh -L 8787:127.0.0.1:8787 user@THEBOX then open http://127.0.0.1:8787/login.
  2. Create the first admin (a person, not the ingest token). Or set SIEM_ADMIN_USER + SIEM_ADMIN_PASSWORD once in the env file, start the service, then delete the password line.
  3. Open Live. If you only ran demo, you will see fake shots. If you tailed a real log, wait for a probe.
  4. Open Settings. Name the dashboard. Put the real server pin as country or lat,lon. Add one row per agent --name.
  5. Open Reports → Insight. 1h / 24h / 7d is a real clock. CSV / JSON export is the same window.
  6. Optional: drop a GeoLite2 / DB-IP .mmdb on the manager and pass --geoip (or re-run the script with --geoip). Without it, countries are coarse.
  7. Optional HTTPS: copy deploy/nginx-gwd.conf.example, certbot, keep ingest off that vhost. See 15 and 18.
  8. Optional block from the dashboard: Settings → Paired hosts → invent a phrase → mint a code → gpewebdefender pair on that box → Approve. Chapter 20.
  9. Optional Status: open Status and click Check on the manager. Pair a host (same as the block step) if you want load / memory / disk from that box too. Nothing is polled until you click. Chapter 21.
  10. Protect the site: plant a canary, confirm /@vite/client is not 200, POST app denials the log cannot see. Chapter 22.
If the UI is empty Demo not running, and no agent / --tail has sent a line yet. Check journalctl -u gpewebdefender -n 50 and that the log path exists and is readable.

Build

From the repo root. Go 1.22+. CGO stays off. You do not need gcc.

HostCommandOutput
Windows go build -o gpewebdefender.exe .\cmd\gpewebdefender gpewebdefender.exe
Linux go build -o gpewebdefender ./cmd/gpewebdefender gpewebdefender
Windows → Linux $env:GOOS="linux"; $env:GOARCH="amd64"; $env:CGO_ENABLED="0"; go build -o gpewebdefender-linux-amd64 .\cmd\gpewebdefender gpewebdefender-linux-amd64
