What it is

A way to look at the boxes you already monitor when you wonder “is that host tight on disk?” It is not a second product and it is not a replacement for htop or a metrics stack.

HostHow a check works
Manager (always listed as manager) Immediate. The process reads /proc (or Windows APIs) and stores a snapshot.
A paired sensor The dashboard queues a stats command. The agent picks it up on its next poll (~4 seconds), posts one snapshot, done.
An ingest-only agent (not paired) Shows on the page as “not paired.” Pair it (ch. 20) if you want specs from that box.
Same pairing as Block The host key that can pick up a ban is the only key that can post a snapshot. The shared ingest token cannot. A viewer can see the last snapshot; only an admin can request a new one.

What you need

  1. Manager and sensors on 0.9.25+. Older agents ignore the stats command.
  2. The sensor is paired and Approved, and the agent unit has --cred so it polls (the install script already does this).
  3. Open Status → Check now on one host, or Check all paired hosts.

All-in-one (manager tails its own log): you can Check the manager with no pairing. Split fleet: pair each box you want on this page. Log shipping still works unpaired.

The Status page

One card per host. After a check you see:

  • Hostname, OS / arch, CPU count, uptime, agent version
  • Memory used / available (and swap if the OS reports it)
  • Load 1 / 5 / 15 (Linux; Windows has no load average)
  • Disk used / free for /, /var, /home when they are distinct mounts (Windows: C:\)
  • A small chart of memory, disk, and load across your previous checks (up to 24 kept, 40 stored)

Check again when you care. The chart is “the last times you asked,” not a 24-hour timeseries. If a host is down, the command expires in two minutes and the last snapshot stays on the card.

API

POST /api/status/checkadminSnapshot the manager now
POST /api/agents/{id}/checkadminQueue stats on that paired host (local = manager)
POST /api/agents/check-alladminQueue every approved host + snapshot the manager
POST /api/agent/statsthat host’s pair keyWhere the sensor posts the snapshot

The ingest Bearer cannot request or post snapshots. Commands expire in 2 minutes if the sensor is down.

What it is not

  • Not a metrics product. No 10-second scrape, no PromQL, no pager.
  • Not FIM. Reading disk free is not watching files. Secret-file alerts still come from the access log (ch. 07 / 14).
  • Not continuous CPU %. Load average is the one-shot number Linux already keeps.
  • Not a reason to skip pairing. Unpaired sensors keep shipping logs; they just cannot answer Check.
