00 · What this is

gpesiem is a web-attack monitor for any site that writes HTTP access logs. It reads those logs, fires rules, and shows you who is probing the box.

Reviewed 2026-08-14 v0.1.0 Monitor, not WAF

One sentence

Tail nginx (or Caddy, or anything that writes a combined/JSON access log), match the line against a small YAML ruleset, store the hit in SQLite, stream it to a local UI.

Name vs job The repo is named like a SIEM because that is how the work started. The shipping product is narrower than a full SIEM: web attacks on your sites and servers. Chapter 01 is the boundary.

Why it exists

OSSEC looked right (small, C, HIDS). Wazuh is the modern fork — and it pillages a small box because of OpenSearch (Java), not because the detector itself is Java.

Thing we looked atWhat was trueWhat we did
OSSEC Light C HIDS. XML, 2008 UX, weak search. Stole the job. Did not take the source.
Wazuh OSSEC + OpenSearch + dashboard. RAM hog is the indexer. Refused the Java pile.
Vector + OpenObserve Great log pipeline. Not a SIEM. No FIM, no SOC, no web-attack content. Did not assemble a log bucket and call it done.
gpesiem Go binary + SQLite + web rules + UI. Built this. Windows and Linux. Comfortable on 1 GB.
