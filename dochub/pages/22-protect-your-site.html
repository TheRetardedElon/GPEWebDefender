Tail nginx / Caddy / Apache (ch. 03). No app code required. The monitor already matches:

Quiet static is on purpose A 200 for /assets/app.css is thrown away. A 200 for /assets/app.js.map or /@vite/client is not. Do not “fix” disk by logging less of those.

Plant canaries (five minutes)

A path no honest user ever opens. Return 404 or 403. Do not link it from the UI.

# any one of these is enough
/.well-known/siem-canary
/__canary__/siem
/api/public/__siem-canary__
/api/public/__canary__/siem

Optional: Disallow it in robots.txt — scanners read that file. The access-log agent fires web.canary.well_known (critical) on the first GET. If the app can POST, also send reason=canary_hit. Both is fine.

Do not ship a front-end dev server

If a product hostname answers GET /@vite/client or serves /src/main.jsx, anyone can read your client source, comments, and sometimes secrets you thought were “build-only.” Serve a production build (vite preview, nginx static, etc.). After that, those alerts should stay at zero. If one comes back, someone put the dev server on the public host again.

What only the app can tell you

Access logs cannot see a failed password in a POST body, a bad webhook HMAC, or “user A opened user B’s invoice.” The app POSTs one JSON event. Same ingest token. Fire-and-forget. Never wait on the monitor. Never send secrets. Full field list: 19.

If you cannot detect IDOR yet, do not send idor. The monitor cannot invent it from nginx. Aliases exist (cross_tenant → idor, arcade_deny → app_deny) so an existing app does not have to rename overnight.

Contain (optional)

Pair the host (ch. 20), then Block from an alert card. Manual only. Viewer and the ingest token cannot. Public IPs only. Status (ch. 21) is a separate click when you want load / disk.

Friday checklist

  1. Manager + first admin. Agent on each box that has an access log. --journal if you care about SSH.
  2. Settings: name, map pin, one row per agent --name.
  3. Hit /.env from your laptop (expect 404). Confirm a recon alert. That proves plane 1.
  4. Plant a canary. Hit it once. Confirm critical. That proves traps.
  5. Confirm GET /@vite/client on the public host is not 200.
  6. App POST for login fails → Reports → Auth · App. Then add IDOR / webhook / key reasons as you can detect them.
  7. Optional: pair + Block. Optional: Status → Check.
