Web authentication

No extra shipper. Any access log already flowing in is enough. Failures are 401 / 403, or a path that looks like a login (/login, /signin, /auth, /wp-login, /session).

Brute force is still web.brute.login and web.scan.403storm on the Live tab. Reports list every fail, not only the threshold crossing.

Linux box authentication

Same agent, extra tail. We keep sshd failures / accepts, invalid users, sudo auth failures, and a few PAM / console lines. Cron and kernel stay on the floor. 

gpewebdefender agent \
  --url http://MONITOR:8787 \
  --token SECRET \
  --name web-1 \
  --tail /var/log/nginx/access.log \
  --journal

# Classic auth.log / secure still works if the file exists:
#   --tail /var/log/auth.log
# Debian 13+ is often journald-only — use --journal.

# Linux-only box (no HTTP):
gpewebdefender agent --url http://MONITOR:8787 --token SECRET --name db-1 --journal
Still not OSSEC This is an auth parser, not FIM, not rootkit, not every facility. If the line is not a login, we drop it.

Application / platform login failures

Access logs cannot see a failed password POST. The application (or an API gateway) must emit a structured event. Never send the password, cookie, or session secret. 

POST /api/ingest
Authorization: Bearer SECRET
Content-Type: application/json
X-SIEM-Source: app-api

{
  "kind": "applogin",
  "src_ip": "203.0.113.9",
  "user": "alice",
  "path": "/api/login",
  "status": 401,
  "outcome": "fail",
  "method": "LOGIN",
  "host": "optional-vhost",
  "ua": "optional",
  "time": "2026-08-15T01:40:00Z"
}
FieldRequiredNotes
kindyesapplogin (aliases: app, login)
src_ipyesClient address as the app saw it (honor X-Forwarded-For only if you trust the hop)
userstronglyUsername or email. Not a password. Empty is allowed but the report is weaker.
outcomeyesfail or ok
statusnoDefaults 401 on fail, 200 on ok
methodnoUse LOGIN so web-brute rules do not double-count
pathnoWhich login route. Helps the path table.

A JSON array of those objects is a batch. Successes are optional; send them if you want a fail/ok ratio. app.login.fail is a low alert per fail. app.login.brute is 8 fails / IP / 2 minutes.

Tenant / site-owner logins

Same ingest as app logins, but tagged so they get their own report tab and map color. Use this for the people who own a site, not staff SSH and not generic /api/login. 

{ "kind": "tenantlogin", "src_ip": "203.0.113.9", "user": "owner@site",
  "path": "/owner/login", "status": 401, "outcome": "fail", "method": "LOGIN" }

# or keep kind=applogin and set role:
{ "kind": "applogin", "role": "tenant", "src_ip": "203.0.113.9", "user": "owner@site",
  "status": 401, "outcome": "fail" }

Aliases for kind: ownerlogin, tenant, owner. Never send the password.

Application probes (kind=secprobe)

When the app itself can see an attack that the access log cannot (a canary route, a rejected webhook signature, a privileged URL that returned 403), POST a small event. The manager matches reason, not your URL layout. 

POST /api/ingest
Authorization: Bearer SECRET
Content-Type: application/json
X-SIEM-Source: app-sec

{ "kind": "secprobe", "src_ip": "203.0.113.9", "reason": "canary_hit",
  "path": "/.well-known/siem-canary", "status": 404 }
reasonMeansRule
canary_hitSomeone requested a planted decoysec.canary.hit
path_probeTraversal, .env, admin path in the URLsec.path.probe
sensitive_deny401/403 on a privileged routesec.authz.deny
webhook_rejectBad webhook signature / authsec.webhook.fail
auth_rate_limit429 on a login routesec.auth.ratelimit
enum_burstMany public-id lookups from one IPsec.enum.burst
app_denyA feature refused without credentialssec.app.deny
idorUser A tried to read user B’s recordsec.idor
priv_escTried to become a more powerful rolesec.priv_esc
key_replayStolen or reused API / device keysec.key_replay
ssrf_outApp blocked a fetch to a private URLsec.ssrf_out
upload_abuseBad or hostile file uploadsec.upload_abuse
ws_abuseLive socket / channel abusesec.ws_abuse
logic_denyPrice / qty / business rule cheatedsec.logic_deny
stepup_bypassTried to skip 2FA / step-upsec.stepup_bypass
score_abuseScore / leaderboard cheat or flood (app already decided)sec.score.abuse
rate_limit429 on a public route (not login)sec.rate.limit
signup_abuseRegistration spray / fake signupssec.signup.abuse

Never send tokens, signatures, or request bodies. Access-log canaries (14) still work if the app cannot POST. The full “do this like ACMECo” walkthrough is 19.
