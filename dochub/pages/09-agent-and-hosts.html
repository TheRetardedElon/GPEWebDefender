09 · Agent & hosts

One manager. Zero or more agents. Same binary. Agents tail files and POST lines — they do not run detection. After you pair a host (ch. 20) they also pull block orders and on-demand status checks. The app can POST on its own — that is plane 2, chapter 19.

Reviewed 2026-08-16 POST /api/ingest

When you need an agent

SetupUse
One host, log on the same box as the UI gpewebdefender serve --tail /var/log/nginx/access.log — no agent
Several web hosts, one monitor box Manager on the monitor. gpewebdefender agent on each web host.
You already have a shipper (Vector, Fluent Bit) POST lines to /api/ingest. Agent is optional.

Flow

flowchart LR
  L1[access.log host A] --> A1[gpewebdefender agent]
  L2[access.log host B] --> A2[gpewebdefender agent]
  A1 -->|batch ≤50 / 500ms| M[gpewebdefender serve]
  A2 --> M
  M --> UI[UI :8787]

Agent buffer is 256 lines. If the manager is down and the buffer fills, lines are dropped (logged as buffer full). v0.1 has no disk queue. Pairing and optional block orders are chapter 20 — shipping logs does not require that.

Commands

# manager (monitor box)
gpewebdefender serve --listen 127.0.0.1:8787 --token SECRET --db /var/lib/gpewebdefender/gpewebdefender.db

# each web host
gpewebdefender agent \
  --url http://MONITOR:8787 \
  --token SECRET \
  --tail /var/log/nginx/access.log \
  --journal \
  --name web-1
DetailBehavior
AuthShared ingest token, or that host’s pair key after Approve. The ingest token never grants block orders.
SourceX-SIEM-Source = --name (default: hostname). Appears in the host dropdown and on each alert.
Linux auth--journal (Debian 13+), or --tail /var/log/auth.log. See 16 and 17.
BodyPlain text, newline-separated access-log lines
FlushEvery 50 lines or 500 ms
HTTP timeout10 seconds per POST
Several hosts on one map Give each agent a stable --name. On the manager, either leave the dropdown on All hosts (every pin at once) or pick one name to cycle the feed. Optional --homes "web-1=40.7,-74.0;edge-eu=DE" places each name on the map. Names are yours — nothing about a specific fleet is compiled in.
Do not expose ingest to the internet Put the manager on localhost or a private NIC. If agents are remote, use a tunnel, tailnet, or nginx allowlist — not a public :8787. See 10.

Pairing (optional)

Log shipping does not need this. Pairing is how an admin can later click Block on an alert and have that host drop the IP in fail2ban / UFW / Windows Firewall. Full chapter: 20. 

# on the manager UI, as admin:
#   Settings → Paired hosts → invent a phrase → Pair a host… → copy the code
#
# on the sensor
gpewebdefender pair --url http://MONITOR:8787 --name web-1 --code ABCD-2341 --block fail2ban
# type the phrase when asked, then Approve the fingerprint in Settings

Existing agents keep shipping with the old token. To enable block they need a binary that includes pair (0.9.19+; 0.9.25+ to answer Status checks), then the three human steps, and --cred on the agent unit so it polls for orders.

After Approve, Status → Check now pulls load / memory / disk from that box once. Same poll as block orders. Chapter 21.
